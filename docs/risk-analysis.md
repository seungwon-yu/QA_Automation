# 리스크와 검증 우선순위

영향 High는 플레이 불가·진행 중단·잘못된 성공 판정, Medium은 표시/분석 지연으로 정의한다. 가능성은 코드 변경 지점과 기존 재현을 근거로 판단하며 실측 발생률이 아니다.

| 위험 | 영향/가능성 | 근거 | 검증·추적 | 잔여 위험 |
| --- | --- | --- | --- | --- |
| 충돌 경계 누락 | High/Medium | 엄격한 부등호·padding·이동 결합 | TC-005-03/05 | 고속 통과 전체 범위 미검증 |
| 공중 연속 점프 | High/Medium | 입력과 상태 분기 | TC-002-02/06 | 장치별 키 반복 미검증 |
| 게임오버 이후 진행 | High/Medium | tick 상태 제한 | TC-003-04 | 엔진 이외 렌더 효과 별도 |
| 마지막 프레임 오판 | High/확인됨 | 수정 전 score=1, matched=false 재현 | HAR-001 | 입력 범위 회귀 유지 |
| 원인 없는 제품/테스트 실패 확정 | High/확인됨 | TypeError 문자열 오분류 | DIAG-001~004 | 규칙 기반 후보이며 사람 검토 필요 |
| 캡처 실패로 로그까지 누락 | Medium/Medium | screenshot 저장이 선행 | EVID-001 | 디스크 쓰기 자체 실패는 수집 불가 |
| 재시작 데이터 잔류 | High/Medium | 상태 여러 필드 초기화 | TC-001-03, TC-006-03 | 영구 저장 기능은 없음 |

위험이 큰 경계·상태·판정 근거를 먼저 보완한다. 단순 TC 개수 증가를 우선순위 근거로 사용하지 않는다.
