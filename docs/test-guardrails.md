# 검증과 수정 단계의 기준

## 실행 단계

기대결과·assertion·제품 규칙을 바꿔 실패를 숨기지 않는다. 원본 결과와 수집 가능한 상태/로그/screenshot을 보존한다. 캡처가 불가능하면 capture-status에 이유를 남긴다. 증거가 부족하면 REVIEW_REQUIRED이다.

## 수정 단계

재현 조건과 기대/실제 차이를 먼저 기록한 뒤, 확인된 제품 코드·테스트·하네스 결함을 수정할 수 있다. 동일 기준으로 재검증하고 관련 회귀를 추가한다. 요구사항 자체가 바뀌면 기존 실패 해결과 구분해 변경 이유를 적는다. 제품 수정 자체를 금지하지 않는다.

## 실험과 재시도

총 시도 횟수는 최초 포함 최대 3회. 반복 검증과 실패 재시도를 구분한다. EXP-001은 격리된 브라우저에 인위적 결함을 주입하는 실험이고 실제 제품 결함 보고와 분리한다. 증거 경로를 실행별로 보존한다.

## 종료

[실행 리포트](test-report.md)에 명령·결과·증거·제한을 기록한다. 통과하지 않은 검증, 원격에서 확인하지 않은 CI, 범위 밖 검증을 완료로 쓰지 않는다.
