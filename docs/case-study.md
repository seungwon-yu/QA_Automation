# 사례: 마지막 허용 프레임을 놓치는 하네스

## 무엇을 검증했는가

HAR-001: 최대 N프레임까지 진행할 수 있다면 N번째 프레임에 조건을 만족한 경우도 성공이어야 한다. 잘못된 실패는 제품 버그로 오인될 수 있어 자동화 도구의 경계도 검증했다.

## 수정 전 재현

```js
new GameHarness().start().runUntil((state) => state.score > 0, 5);
```

2026-09-13 평가에서 최종 score=1인데 matched=false 반환을 확인했다. 분류는 TEST_FAIL(하네스 결함)이며 게임 제품 결함이 아니다.

## 원인과 변경

기존 반복문은 프레임 진행 전에만 조건을 확인해 마지막 tick 이후 검사하지 않았다. 초기 상태부터 마지막 허용 프레임까지 포함하도록 수정하고 허용 수를 넘겨 진행하지 않게 했다.

## 재검증

`tests/unit/portfolioRegression.test.js`에서 초기·중간·마지막·불충족·0프레임 조건을 확인한다. 실제 점수 조건도 유지했다. 최신 실행 증거는 [실행 리포트](test-report.md)에 있다.

## 별도 실험

EXP-001은 실제 겹침을 확인한 뒤 브라우저 인스턴스에서 충돌 판정을 비활성화하여 테스트가 실패를 잡는지 검증한다. 인위적인 결함 검출 실험이며 출시 제품에서 발견한 버그라고 주장하지 않는다.

## 설명할 수 있어야 할 질문

왜 제품과 하네스 결함을 구분했는가? 마지막 프레임을 포함한다는 계약은 어디에 있는가? 수정 후 초과 실행은 없는가? 기존 테스트가 통과한 이유는 무엇인가?

## 추가 사례: 재시작 관찰 시점 경쟁

4개 E2E를 3회 실행하자 11개 통과·1개 실패가 발생했다. UI의 0점을 확인한 후 내부 상태를 읽을 때 시간이 흘러 score=1이었다. 브라우저 clock으로 검증 시점을 고정하고 HUD 갱신 한 프레임만 진행한 뒤 같은 score=0 assertion을 확인했다. 재검증은 12/12 통과했다. 실제 시간 진행을 제거한 목적은 재시작 순간의 계약을 검증하기 위해서이며, 게임의 점수 증가 규칙을 바꾼 것이 아니다.
