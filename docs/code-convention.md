# 러너 QA 코드 작성 기준

JavaScript ESM, 문자열 쌍따옴표, 세미콜론, 2칸 들여쓰기를 사용한다. 함수/변수는 camelCase, 클래스는 UpperCamelCase이다. 게임 상태·입력·충돌처럼 도메인이 드러나는 이름을 사용한다.

엔진은 게임 규칙, 하네스는 제어/관찰, 테스트는 기대결과, fixture는 증거 수집을 담당한다. 상태를 검증하는 코드를 분류기나 렌더러에 숨기지 않는다. 랜덤·시간 의존성을 명시한다.

테스트는 사전조건→행동→기대결과를 읽을 수 있어야 한다. 경계 기대값을 제품 판정 함수로 재계산하지 않는다. 결함 수정은 재현 사례와 관련 회귀로 검증한다. 작은 문서 변경에 불필요한 테스트를 추가하지 않는다.
Java DTO/Controller 등 이 저장소에서 사용하지 않는 규칙은 두지 않는다.
