# 테스트 계획

## 목적과 범위

게임 QA 신입 관점에서 핵심 규칙의 위험을 선정하고, 통제한 조건으로 재현하며, 결과를 설명한다. 베이시스는 [게임 규칙](game-rules.md), 우선순위는 [리스크 분석](risk-analysis.md)이다.

범위: 시작·점프·충돌 경계·게임오버 정지·재시작·점수·장애물·브라우저 입력 연결. 자동화 자체의 판정/증거 실패도 별도 검증한다. 다중 브라우저, 장시간 성능, 접근성 전체 감사는 이번 완료 조건에서 제외한다.

## 시작 조건

Node/npm 의존성 설치, 브라우저 바이너리 준비, 테스트용 로컬 포트 사용 가능. 각 엔진 TC는 새 인스턴스를 생성한다. 경계값 TC는 이동 없는 dt=0 판정과 실제 1프레임 통합을 분리한다.

## 종료 조건

1. 범위 내 TC와 구현 연결이 존재하고 단위/E2E가 통과한다.
2. 마지막 프레임·충돌 경계의 재현 사례가 회귀 테스트로 남는다.
3. 의도 실패 시 증거가 생성되고 캡처 불가도 기록된다.
4. 현재 결과/미실행/잔여 위험을 보고한다. GitHub 원격 CI 실행은 별도 확인한다.

테스트 수와 TC 수를 혼동하지 않는다. 반복 검증은 동일 정상 E2E 4개를 3회 실행하는 제한된 관찰이며 장기 안정성 인증이 아니다. [완성도 판단](completion-review.md)
